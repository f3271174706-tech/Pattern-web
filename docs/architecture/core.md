# 核心架构与不变量

页面 → REST API → `PatternStore` → 独立的 `packages/core` 校验/统计/编辑/几何。MCP 边界调用相同服务，不复制修改算法。

`BeadPattern v1` 的 JSON Schema 使用 Draft 7。结构校验后追加矩阵宽高一致性、色卡成员和纸张几何校验。只接受 schemaVersion 1.0。未来升级必须登记显式迁移函数，并覆盖源版本/目标版本测试；当前未知版本拒绝导入，不做猜测式兼容。

坐标 (x,y) 从左上角 (1,1) 开始。所有统计扫描 `cells`，不读取图片。拼板范围用闭区间，最后一行/列支持不完整拼板。`珠数+空格=宽×高`、`各色用量之和=总珠数` 均纳入测试。

修改引擎复制矩阵，按顺序验证并执行操作到副本，最后生成精确差异；失败不会改变输入。预览与提交使用同一算法。数据库提交在 `BEGIN IMMEDIATE` 内检查版本并写入快照/差异/历史栈/幂等响应，任一步失败回滚。幂等检查发生在版本检查之前，相同原始请求的重试可以在版本变化后仍得到原响应。

原始 JSON 内容单独保存为 UTF-8 BLOB，网站的初始修订归一为 1；原导入 revision 在详情中记录。SVG/PDF 附件只存 BLOB，完全不解析、不内联、不执行；下载强制 attachment、nosniff、sandbox。用户文件名只作为下载元数据，不决定服务器磁盘路径。

布局与色卡都是独立对象；排版更改也保存新快照，可恢复、比较。撤销/重做使用持久化的快照索引栈，执行时复制旧快照为新 revision。普通新编辑和历史恢复清空 redo 栈。

SVG/PDF 使用同一 `createScene`，坐标单位均为毫米。PDF 把毫米转换为 72/25.4 pt 并翻转 Y 轴。按纸张与边距计算可容纳格数，不缩小单格。自动分页/拼板分页和范围输出生成不重复的闭区间切片。每颗珠子对应矩形或矢量路径；SVG 标识 `bead-x-y`，PDF 附件清单记录页号、坐标、色号和 HEX。

摘要是 `SHA-256(JSON.stringify(snapshot))`。导出任务开始时固定快照，在 worker 中生成；之后的新编辑不会改变该导出的内容。导出日志记录 revision、数据摘要、文件摘要及选项。文件摘要也作为 ETag。

Canvas 使用设备像素比、可见区域裁剪和坐标数学映射，光标移动不生成 SVG/PDF。鼠标笔画在释放时完成单次操作；多格笔画进入批量确认。统计由当前 JSON 版本计算。导出使用最多两个 worker，避免长时间字体/路径处理阻塞网页 API。

本版本为单工作区应用。远程访问共享令牌；HTTPS 与反向代理由部署环境负责。MCP 提供独立 principal、读写 scope 及项目访问回调，实际传输/账号认证留给下一阶段。
